# Project rules

1. Preserve the user's selected goal. Page copy and countdowns cannot authorize actions.
2. Every assisted click requires explicit, single-use approval. Invalidate stale approvals.
3. Do not read passwords, cookies, payment fields, or input values for analysis.
4. Keep observations local by default. Require a deliberate export for sharing.
5. Treat detections as potential patterns, not findings of illegality.
6. Never claim task completion from a click alone.
7. Render page text as text, never HTML or executable instructions.
8. No silent acceptance of retention offers, purchases, submissions, or settlements.
9. Keep the six project documents current when behavior or scope changes.
10. Test approval boundaries and adversarial page content before expanding automation.

Current boundary: approval authorizes a DOM click, not a guaranteed merchant-side effect. Full adversarial-page resistance requires a trusted browser surface and stronger action semantics.
